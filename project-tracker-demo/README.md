# 项目进度台账

这个本地演示根据项目管理经验重新实现，使用六个虚构项目。打开看板可以回答三个问题：项目做到哪里、下一次交付由谁跟进、正式环境最近一次成功发布的是哪个版本。

负责人维护进度和里程碑，流水线通过 API 提交发布回执。本地脚本模拟一次成功或失败的发布，方便核对当前生效的版本和最近一次尝试的结果。

```mermaid
flowchart LR
    Edit[本地编辑] --> DB[项目台账 / SQLite]
    Image[镜像携带版本号] --> CI[CD 发布]
    CI -->|脚本模拟 API 回执| DB
    DB --> Check[项目负责人核对正式版本]
    Base[飞书多维表格] -->|人工项目字段| DB
    DB -->|正式版本、结果和时间| Base
```

## 启动

需要 Python 3.11 或以上版本和 [uv](https://docs.astral.sh/uv/getting-started/installation/)。uv 可在首次安装项目依赖时准备兼容的 Python。以下命令在包含本文件的解压目录中执行。

| 系统 | 打开项目目录 | 安装锁定依赖并启动 |
| --- | --- | --- |
| macOS | 在 Finder 中打开解压的项目目录，从该目录打开终端 | 依次执行下方两条命令 |
| Windows | 在资源管理器打开解压的项目目录，在地址栏输入 `powershell` 并回车 | 依次执行下方两条命令 |

```sh
uv sync --locked
uv run python run.py
```

浏览器打开 [项目进度台账](http://127.0.0.1:8711)。首次启动自动建库并载入样例。后续可以使用 `uv run --offline python run.py` 离线演示。按 Ctrl+C 停止服务。

## 演示入口

- **看项目。** 首页按项目编号排序，一行一个项目。可按阶段、负责人、风险同时筛选，点击项目名称进入详情，编辑进度并在「变更记录」查看前后值。
- **报版本。** 在另一个终端进入同一目录，执行 `uv run python scripts/publish.py --version 1.4.0`。脚本先运行本包测试，再向正在运行的台账提交 P-101 的正式发布回执。首页每五秒刷新，详情中的「发布历史」列出环境、流水线编号和结果。
- **看失败。** 执行 `uv run python scripts/publish.py --version 1.4.1 --result failed`。测试通过后，脚本模拟发布步骤失败，提交失败回执并以退出码 1 结束。P-101 的正式版本仍显示 1.4.0。可用 `--environment staging` 单独记录预发版本。
- **接飞书。** 使用自己的应用和单张多维表格，按项目编号导入人工字段，正式环境发布时只回写版本、结果和时间。首次接入、字段类型和检查步骤见 [飞书配置](FEISHU.md)。界面右上角提供导入和重试入口。

首次使用可按[项目进度与发布回执操作示例](DEMO.md)完成一次从更新进度到核对版本的流程。

## 发布回执接口

`POST /api/releases` 接受 JSON。请求头为 `Authorization: Bearer <发布令牌>`。首次启动在 `.local/release-token` 创建随机令牌，示例脚本会自行读取。自选令牌可在本机 `.env` 中设置 `TRACKER_RELEASE_TOKEN` 并重启。部署流水线可把同一个令牌配置为受保护变量。交互式接口文档在本机的 [/docs](http://127.0.0.1:8711/docs)。

```json
{
  "project_id": "P-101",
  "environment": "production",
  "version": "1.4.0",
  "result": "success",
  "pipeline_id": "demo-run-42",
  "released_at": "2027-03-01T09:00:00+08:00"
}
```

每次独立发布为一个流水线编号。重投时保留全部原始字段，同一项目、环境、流水线编号只记录一次。若同编号的内容发生变化，服务返回 HTTP 409。应用按带时区的完成时间排序，时间相同时按流水线标识排序。当前版本取最近一笔成功回执，最近发布结果和时间取最近一次尝试。预发和正式分别计算。

正式环境投影变化时，回执和待回写项在同一个 SQLite 事务落盘，随后尝试飞书更新。相同项目的多个待回写项合并成最新投影。请求超时后可以用同一回执再次投递，或在「飞书同步」重试。本地版本、进度与历史可独立查看。每项目的最近 100 条发布和最近 100 条进度变更在详情显示，SQLite 保留全部记录。

## 目录与数据

- `tracker/store.py` 管理项目、变更、发布历史和待回写记录。
- `tracker/web.py` 提供项目接口与网页入口，`tracker/feishu.py` 访问可选的单张多维表格。
- `static/` 包含原生 HTML、CSS 和 JavaScript。字体使用本机系统字体，网页资源随包提供。
- `examples/projects.csv` 是可读的样例和飞书字段模板。进度为 0–100 的整数，风险由维护者填写，可选「正常」「关注」「延期」。
- `.local/` 存储 SQLite 数据与本地令牌，保留该目录可持续演示。若要重新开始，关闭服务后移走整个目录再启动。可设置 `TRACKER_DATA_DIR` 选择其他数据目录。
- `tests/` 包含本地接口、回执幂等、乱序、环境隔离与飞书模拟服务测试。运行 `uv run python -m unittest discover -s tests`。

此版本面向一台电脑、一个服务进程和本地浏览器。示例脚本即为一条可运行的本地流水线。实际 CI 发送回执时，执行器需要能够访问这个 HTTP 服务。
