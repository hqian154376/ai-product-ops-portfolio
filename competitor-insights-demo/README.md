# 竞品观察室 · 设计工具研究决策台

**下一轮迭代，应该先修局部编辑入口，还是先验证选区精度？** 这个可在本机运行的工作台，把两款虚构 AI 设计工具的任务走查、版本公告和用户反馈放在一起，帮助研究者决定先做什么、结论凭什么成立，以及新版本出现后该撤回哪条建议。

本项目为离职后基于过往产品研究场景重新实现的演示。墨汀、溪屿案例的产品名、材料、日期与访谈摘录均为虚构；来源采集页另使用真实公开官方文档。

[用户流程、模块架构与大模型的职责](ARCHITECTURE.md) · [版本走查与反馈复核教程](DEMO.md) · [真实 DeepSeek 调用记录](MODEL-RUN.md)

**新增公开网页采集。** 首页点「来源采集」，可一键采集配置中的真实 Krita、GIMP 官方文档，经 Trafilatura 提取正文、内容去重与快照保存后，确认原文摘录即可进入 Agent 研究。无需自己制作 CSV。[采集流程、架构与开源选型](COLLECTION.md)。虚构 AI 产品案例与真实图像工具文档分别研究，官方描述与操作实测分别标记。

**查看真实模型回放。** 解压后双击 `static/model-replay.html`，或在运行中的首页点「查看真实模型回放」。先读“编辑入口可转回归”的判断，点版本走查编号核对，再看“选区边界仍需复测”引用的反馈和反例。这份历史回放可离线浏览。

## 在本机运行

安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)。在 macOS 终端或 Windows PowerShell 中进入包含 `run.py` 的目录，执行：

```sh
uv sync --locked --python 3.12
uv run python run.py
```

打开 [本机研究决策台](http://127.0.0.1:8712)。第一次安装需要联网，随后可用 `uv run --offline python run.py` 运行本地规则版。SQLite 数据保存在 `runtime/walkthroughs.sqlite3`，按 Ctrl+C 可停止。首次使用可按[操作示例](DEMO.md)比较两个版本并复核一条反馈。

## 研究者可以做什么

| 研究问题 | 实际产物 |
| --- | --- |
| 哪个断点值得优先改？ | 机会清单给出优先级、依据、验证动作和指标口径。实测的阻碍、尚待复测的分歧、已修复的回归项分别处理。 |
| 两款工具在哪些方面有差距？ | 逐项对照首图生成、多轮迭代、编辑衔接、选区精度、参考约束、版本恢复与交付导出。可从每格追到日期、版本和来源原文。资料空白标为未知。 |
| 上次判断今天还成立吗？ | 比较同一产品、同一步骤的前后走查。可按材料日期筛选；报告保存当时的矩阵、引用、建议和执行记录，之后补材料或订正走查仍可打开旧报告。 |

**怎样读结论。** v1 公告里的“继续编辑”没有说明是否保留底图，同期走查却复现了重新上传。研究台以走查判断这个操作，并保留公告与反馈供复核。两段来自同一次访谈的摘录保留两个证据编号，但只算一份来源。若新版本公告称“边缘已改善”，访谈仍提到椅腿被误改，则列为待复测，并给出可执行的选区测试与分子、分母。口径用于设计下一次实验，本包没有线上转化率或留存率数据。

## 用自己的材料做第二次研究

从「导入研究材料」选择对应模板。两种 UTF-8 CSV 都支持先校验后整批写入。汇总重复投递的来源时，以稳定证据编号为准。

- **任务走查**使用 [import-example.csv](samples/import-example.csv)。每行记录一个产品在指定日期和版本完成某一步骤的表现。一个新产品先用这个模板登记。相同产品、日期和步骤可以订正，先前保存的报告保留原文。
- **公告或反馈**使用 [source-import-example.csv](samples/source-import-example.csv)。每条摘录登记证据编号、产品、版本、日期、能力、来源类型、材料编号、出处、倾向、原文。样例里一份公告称支持透明背景导出，一位用户却遇到白底。同一份材料的多条摘录共用 `origin`。同一 `id` 与内容重复时自动跳过，同一 `id` 对应不同内容时提示另设编号。
- **复核矛盾说法**可从走查入口导入 [verification-example.csv](samples/verification-example.csv)。后四项能力均可记录 `pass`、`fail` 或 `unknown`。样例是一条虚构的 PNG alpha 通道检查记录；程序导入这条走查并关联复核依据，展示如何从两份相反说法走到一条有明确适用范围的判断。
- **按日期复盘**时，默认取所选产品最近走查日。刚导入的材料如果晚于这个日期，可显式选择更晚的截止日。能力判断按当时可核对的产品版本取材，旧材料在证据库中保留其原始日期与版本。

## 从反馈变化到实测结论

在「反馈雷达」点击「载入两周虚构反馈」。以干净样例为起点，选择七天窗口和 2026-10-10 作为截止日：溪屿的透明导出在本期 7 份独立反馈来源中有 4 份提及，上期为 3 份中的 1 份。本期有 3 份独立负向来源，同时保留了成功导出的反例。展开渠道样本构成，检查反馈是否集中在访谈、社区或客服；主题比例只描述这批样本。

可以从异动「登记跟进」，再从研究台走查入口导入透明 PNG 的[复测记录](samples/verification-example.csv)。回到跟进记录，挂上该次实测、填写结论、标为已复核。原始触发证据和后来用来复核的实测分别保存。每个主题也能带着产品、窗口、日期与问题进入研究台生成报告。

反馈 CSV 支持可选末列 `channel`，值为 `interview`、`community`、`support` 或 `unknown`。兼容此前无该列的材料，未登记的渠道显示未知。主题和趋势采用透明的匹配与统计规则，倾向取自原始材料的登记值。导入流程不依赖外部网站抓取。

## 模型如何参与

不填写 Key 时，选择「机会优先级」「能力对标」或「版本复验」即可得到可重复的规则分析。需要自由提问时，在项目目录将 `.env.example` 复制成 `.env`，填写 `LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`，重启。模型服务须支持 OpenAI 兼容 Chat Completions 和函数工具调用，个人凭据只由本机后端读取。

模型可对标能力、检查版本变化、读取反馈趋势、检索材料目录、打开证据原文。服务按研究对象与截止日限定查询范围，并核验报告引用属于本轮确实打开过的原文。可以从执行记录核对实际工具调用。涉及反馈趋势时，程序单列表格核算窗口、渠道和正反例，模型另写实验建议与局限。程序用于核算的依据与模型真正打开、引用的原文分别记账。**引用有效说明出处可查；判断是否准确，仍可以点回原文逐条核实。** 选择模型模式后，问题和读取的材料会发给所配置的服务。

## 代码和验证入口

| 入口 | 负责什么 |
| --- | --- |
| `insights/catalog.py`、`insights/materials.py` | 走查与来源导入、SQLite 存储、稳定证据编号 |
| `insights/research.py` | 时间截面、七项能力矩阵、证据分歧与机会排序 |
| `insights/strategy_agent.py` | 模型工具循环、读取记录、引用核验与报告生成 |
| `insights/app.py`、`static/` | 本地 API、研究决策台、原始走查及两类报告历史 |

运行 `uv run --offline python -m unittest discover -s tests`。测试使用虚构数据和模拟模型，覆盖来源冲突、重复导入、日期边界、新旧版本判断、快照、模型权限错误与无效引用。首次使用自己的模型时，可问“墨汀新版的哪些问题已复验，哪些说法还有矛盾？”，打开引用核对。作品集原有的双项目视频记录了此前走查版的 DeepSeek 和飞书演示；新研究台的本地流程见仓库首页。
